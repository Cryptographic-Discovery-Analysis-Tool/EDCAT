- **URL:** https://www.rfc-editor.org/rfc/rfc10024.txt (info page: https://www.rfc-editor.org/info/rfc10024/)

This is the RFC-Editor-published successor to the expired individual/WG draft
`draft-ietf-tls-ecdhe-mlkem` -- no in-repo document previously cited that
draft, so there was nothing else to update to point at this RFC instead
(checked: `grep -r draft-ietf-tls-ecdhe-mlkem` across the repo returns no
hits). This file is the first citation of the standard in this repo.

## Named hybrid groups (Abstract; §1)

Exact sentence:

- "This document defines three hybrid key agreement mechanisms for TLS 1.3
  -- X25519MLKEM768, SecP256r1MLKEM768, and SecP384r1MLKEM1024 -- that
  combine the post-quantum ML-KEM (Module-Lattice-Based Key Encapsulation
  Mechanism) with an ECDHE (Ephemeral Elliptic Curve Diffie-Hellman)
  exchange."

`X25519MLKEM768` was already cited in this repo from
docs/architecture/Pramana_Ledger_Spec.md §5.1 (a negotiated-group
observation, not a standards citation). `SecP256r1MLKEM768` and
`SecP384r1MLKEM1024` were previously recorded in data/crypto_families.yaml
as "searched for and NOT found in any in-repo document" -- this RFC is that
citation now.

## Group-name spelling note (§3)

- "Note: The group name X25519MLKEM768 does not adhere to the naming
  convention outlined in Section 3.2 of [RFC9954]. Specifically, the order
  of shares in the concatenation has been reversed. This is due to
  historical reasons." -- the RFC keeps the wire-observed casing
  (`X25519MLKEM768`, `SecP256r1MLKEM768`, `SecP384r1MLKEM1024`) rather than
  a normalized form, which matches what scanners (sslyze, OpenSSL) already
  report and what this repo's `family_aliases` naming-identity rows expect.
